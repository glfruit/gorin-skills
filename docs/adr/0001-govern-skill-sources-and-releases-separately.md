# Separate skill sources from releases

Gorin Skills is the authoritative source for first-party skills, but repository presence no longer implies publication. Stable capability-domain paths hold standard Agent Skills sources, per-skill manifests own governance metadata, and generated catalogs, profiles, target packages, and managed installations expose only lifecycle-approved skills; this adds a build layer in exchange for stable paths, explicit maintenance responsibility, reproducible releases, and safe multi-harness installation.

## Consequences

- Existing skills must be requalified instead of inheriting release status from their current directory.
- Third-party code is either an external source, a pinned managed mirror, or a maintained `gorin-*` adaptation.
- Codex, Claude Code, and OpenClaw differences are generated by target adapters rather than maintained as source forks.
- Legacy names remain compatibility aliases for one major release and never own a second implementation.
